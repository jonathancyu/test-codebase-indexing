# API Overview

## Overview

!!! Note
    For details on how this API is deployed to AWS infrastructure, see the [API Infrastructure Documentation](../infra/cdk/index.md).

The APIs are powered by a single FastAPI application defined in `backend/backend_code/api/app.py`. This application serves as the central routing hub for all API endpoints. It is also where any middleware is defined.

All routes are organized in the `backend/backend_code/api/router/` directory, with each api path having its own router module. For example, the `users` api path has its own router module `users.py`.

## Running the API Server Locally

While the API is deployed as a Lambda function in production, it can be run as a standard FastAPI server during development. This allows developers to use FastAPI's built-in development server, automatic documentation (via `/docs`), and debugging tools. To run the server locally you must first authenticate with AWS using the aws cli.

```bash
aws sso login --profile {your-profile}
export AWS_PROFILE={your-profile}
```

Once authenticated to aws, you can run the server using the included Docker containers.  More information about running local development can be found [here](../development/index.md).

## Adding a New API Path or Method

### Create a new router module

To add a new API path or method (ie adding a `POST` method to a path which only has a `GET` method), you must first create a new router module in the `backend/backend_code/api/router/` directory if it does not already exist. This router module should be named after the api path and should be named after the api path. For example, if the api path is `users`, the router module should be named `users.py`.

### Define the API output

When you create a new path or method, your API output MUST be strongly typed using a Pydantic model. These models are defined in the each router module file. By using these models, you ensure that the API output is consistent, follows a standard format, has automated documentation generated for it, and is easier to consume by clients (frontend, other services, etc).

### Add the router to the FastAPI app

Once the router module is created, you must add the router to the main FastAPI application in the `backend/backend_code/api/app.py` file. This is done by importing the router module and adding it to the `app.include_router` method.

```python
app.include_router(users.router)
```

### Update the API Gateway routes in the CDK stack

At this point, you can run the server locally and test the new api path or method. However, in order for this new api path or method to be deployed to the production environment in AWS, you must also update the API gateway routes in the `infra/src/stacks/infra-stack.ts` file. This file is used to register all the routers with the API Gateway and Cognito Authorizer.

### Update the environment variables

If your new api path or method requires the usage of new environment variables, you will need to follow the instructions in the [Environment Variables Documentation](../infra/environment-variables/index.md) to add them to the AWS Secrets Manager. You will also need to update the `backend/tests/test_config.py` file to load the new environment variables when the server is started. This script has examples for loading environment variables from the AWS Secrets Manager secret as well as from a AWS CloudFormation stack output. Making these changes will allow you to run the server locally and load the new environment variables when the server is started.

### Update the API specs

Once all of this development is complete, you will also need to update the API specs. The API specs are defined in the `docs/docs/api/openapi.json` file. This file is automatically generated by the FastAPI application when you run the server locally. You can automatically generate the API specs by running the following command from the root of the repository. Please note that this command will overwrite the `docs/docs/api/openapi.json` file with the latest API specs.

```bash
python docs/generate_openapi_json.py
```

Once this is done, your changes to the API specs will be reflected in the [API Specs Documentation](api-specs.md).
